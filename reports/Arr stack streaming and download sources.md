# Swap public torrents for curated Usenet indexers

Streaming a file while it is still downloading is possible in a Sonarr/Radarr/Jellyfin stack, but only by going around the Arr import pipeline. You can play a partial file from qBittorrent in sequential mode, or you can use debrid or Usenet "virtual filesystem" tools that tell Sonarr a download is complete before any bytes are stored locally. On Windows 11 Home with Docker Desktop, the first method works. The second mostly breaks, because Docker Desktop does not reliably support the FUSE mount propagation those tools depend on. Public torrents are not the best acquisition method for this user. They are free and need no extra software, but they score worst on the two risks that matter most here. They put your home IP in front of every peer and monitoring firm in the swarm, and they are the main channel for the 2024-2026 wave of fake-episode infostealers, including an October 2026 fake South Park episode that Sonarr grabbed automatically. A paid Usenet setup costs about $3-8 a month and downloads over SSL with no peers, so a VPN is optional. Good Usenet indexers are moderated, which public trackers are not, and fast downloads make "watch while downloading" largely unnecessary. The recommendation for a South African user with no VPN who was just infected: clean up after the infostealer first, then buy Usenet on Black Friday 2026 pricing, keep torrents only as a hardened, VPN-routed fallback, and treat debrid as an optional add-on, not the foundation. Downloading copyrighted content without permission is illegal in most jurisdictions, South Africa included. This report describes the technology and the risks neutrally.

## Streaming mid-download means working around Sonarr's import

Sonarr and Radarr cannot import a partial file. Completed Download Handling polls the download client's API, and "Sonarr will only start importing once the job is flagged as completed" ([Sonarr forum](https://forums.sonarr.tv/t/completed-download-handler-on-season-packs-only-picking-up-first-episode-or-two/22222)). Moderators describe it as the most reliable import path ([Sonarr forum](https://forums.sonarr.tv/t/previous-download-handling/38907)), and I found no setting or tool that imports a genuinely in-progress torrent into the Arr-managed library. Any watch-while-downloading setup therefore runs beside the Arr flow, not inside it.

For torrents, the usual technique is **qBittorrent's sequential download plus "download first and last piece first."** Sequential mode requests pieces in file order instead of rarest-first. The first/last option matters because container metadata, such as the MP4 moov atom or the MKV index, often sits at the end of the file, and a player may refuse to open the file without it ([qBittorrent forum](https://forum.qbittorrent.org/viewtopic.php?p=21439)). One user reports opening a sequentially downloading .mkv in Jellyfin and watching it while the download stayed ahead of the playhead ([Lemmy](https://lemmy.imagisphe.re/post/817767)). In practice you add a separate Jellyfin library pointed at the download folder and wait for it to be scanned. This is less convenient than it sounds. Jellyfin's real-time monitoring relies on inotify ([Jellyfin forum](https://forum.jellyfin.org/t-solved-real-time-monitoring-not-working-on-some-libraries)), and Docker's WSL2 integration delivers file-change events only for files on the Linux filesystem, not for Windows bind mounts ([Docker forum](https://forums.docker.com/t/volumes-bind-mounts-of-windows-directories-appears-to-be-broken-in-docker-desktop-wsl2-integration/97167)). The default library scan runs only every 12 hours ([Jellyfin forum](https://forum.jellyfin.org/t-new-elements-not-automatically-scanned-recognized-why)), so you will often trigger the scan by hand. Season packs need the unwanted episodes set to "Do not download" ([qBittorrent forum](https://forum.qbittorrent.org/viewtopic.php?p=23302)). Sequential fetching also makes later pieces rarer for other peers and stalls when peers are slow ([qBittorrent forum](https://forum.qbittorrent.org/viewtopic.php?p=21439)). Windows adds one more problem: Sonarr reports "file already in use by another process" when another program holds the file ([Sonarr forum](https://forums.sonarr.tv/t/couldnt-import-episode-file-already-in-use-by-another-process/22068)), so Jellyfin transcoding a file at the moment it completes could block the import. That last point is my inference, and how far it applies inside WSL2 is untested. No source documents what Jellyfin does when you seek past the downloaded point. Expect a stall.

## Debrid and Usenet mounts make "complete" instant, but Docker Desktop breaks them

The more elegant approach skips local downloading altogether. **Decypharr** presents itself to Sonarr and Radarr as a qBittorrent or SABnzbd client. It checks whether a release is already cached at a debrid provider (Real-Debrid, TorBox, AllDebrid and others), mounts the cached files, and hands the Arrs symlinks that they treat as a completed download. Jellyfin then streams the file from the debrid server on demand ([corelab Decypharr guide](https://corelab.tech/decypharr-setup-guide/); [GitHub](https://github.com/sirrobot01/decypharr)). zurg plus rclone ([ElfHosted](https://docs.elfhosted.com/app/zurg)) and Riven's RivenVFS ([Riven docs](https://mintlify.wiki/rivenmedia/riven/introduction)) do the same job in other ways. For Usenet, **nzbdav** serves NZB contents as a WebDAV filesystem that streams articles with seeking, and it exposes a SABnzbd-compatible API, so the Arrs "complete" at once. Its README now says the project is unmaintained, and versions 0.2.46 to 0.6.1 had an auth-bypass vulnerability that was patched in images tagged `+260317` ([nzbdav README](https://github.com/nzbdav-dev/nzbdav)). AltMount is a newer Go alternative ([GitHub](https://github.com/javi11/altmount)). With these tools, "watch while downloading" stops being a problem: the library entry appears in seconds and playback starts almost at once.

They share one dependency that works against this user's platform: a FUSE mount shared between containers through `rshared`/`rslave` propagation ([corelab](https://corelab.tech/decypharr-setup-guide/)). The pd_zurg project states flatly that **"Docker Desktop CANNOT be used"** because it lacks the mount propagation rclone mounts need ([pd_zurg](https://github.com/I-am-PUID-0/pd_zurg)). Users report that FUSE mounts created inside Docker Desktop containers appear empty on the host ([Docker forum](https://forums.docker.com/t/make-mount-point-accesible-from-container-to-host-rshared-not-working/108759)). An rclone drive letter mounted on Windows was not visible to WSL2 containers ([rclone forum](https://forum.rclone.org/t/mapping-to-rclone-mount-from-within-windows-docker-desktop-containers/33002)). The workarounds are to run Docker Engine directly inside an Ubuntu WSL2 distro instead of Docker Desktop, or to run zurg/rclone natively with WinFsp ([zurg WINDOWS.md](https://raw.githubusercontent.com/debridmediamanager/zurg-public/HEAD/WINDOWS.md)) alongside a native Jellyfin. I found no first-hand report of Decypharr or nzbdav running on Docker Desktop for Windows. **Gelato** is the exception, because it streams over HTTP without FUSE. This Jellyfin plugin swaps Jellyfin's search for Stremio-addon results, which resolve on demand ([JellyWatch](https://jellywatch.app/blog/jellyfin-gelato-stremio-integration-plugin-2026)). It needs AIOStreams plus a debrid or Usenet account, and support lags after major Jellyfin releases ([ElfHosted](https://docs.elfhosted.com/guides/media/stremio-addons-in-jellyfin/)). Gelato also bypasses Jellyseerr and the Arrs completely, so it replaces the stack you built rather than extending it. Stremio with Torrentio and no debrid account is plain P2P from your own IP, with the same exposure as torrenting. That point is an inference, not sourced.

## Public torrents score worst on the two risks that bit this user

The table below summarises the notes as of October 2026. Prices for Real-Debrid and TorBox come from third-party sources, because the official pages did not render.

| Factor | Public torrents | Usenet (provider + indexers) | Debrid (TorBox / RD / AllDebrid) | Stremio-style on-demand |
|---|---|---|---|---|
| Speed | Depends on peer count; thin from SA | Near line speed with enough connections | Instant if cached; uncached is swarm-speed | Instant if cached via debrid |
| Availability | Broadest, including old/niche | Strong for new TV/film; takedowns cause gaps | Only what is cached; RD lost much in 2026 | Same as the debrid/Usenet backend |
| Cost | Free + VPN | ~$3-8/mo all-in | ~€3-$12/mo | Debrid cost + optional host |
| Home-IP exposure | High without VPN | Low (SSL to provider only) | Low (service joins swarm) | Low with debrid; high P2P-only |
| VPN need | Essential, with port forwarding | Optional | Unnecessary; can trigger bans | As per backend |
| Fake/malware exposure | Highest | Lower with curated indexers | High if fed from public indexers | High (same public sources) |
| Reliability | Swarm-dependent | High with two backbones | Exposed to provider policy shifts | Plugin lag, provider policy |
| Setup on Docker Desktop | Simple (+ gluetun) | Simple (SABnzbd) | Hard (FUSE propagation) | Moderate (HTTP, no FUSE) |

**Privacy.** BitTorrent shows your public IP to every peer, and that is how monitoring firms generate the notices they send through ISPs. In South Africa, notices come from international monitoring firms and are passed on by upstream providers ([MyBroadband](https://mybroadband.co.za/news/broadband/20116-be-warned.html)). A 2011 survey found that Afrihost, MWEB and Axxess forwarded them, while Telkom, Vodacom and Web Africa did not ([MyGaming/MyBroadband](https://mygaming.co.za/news/business/11650-sa-s-isps-who-sends-copyright-infringement-notices)). I found no newer ISP-by-ISP data, so treat any large FTTH retailer as potentially forwarding. Enforcement against individual downloaders looks rare. ISPA's formal take-down process targets hosted content ([ISPA](https://ispa.org.za/press-releases/covid-19-shines-spotlight-on-website-take-downs/)). ISPs said in 2024 that blocking would need a court order ([Techpoint Africa](https://techpoint.africa/2024/09/05/multichoice-to-combat-illegal-streaming-websites)). Irdeto has nevertheless warned that attention "will begin shifting from distributors to users" ([MyBroadband](https://mybroadband.co.za/news/broadcasting/596339-warning-to-south-africans-using-pirate-streaming-apps.html)). The Copyright Amendment Bill went back to Parliament after the Constitutional Court's 26 June 2026 judgment ([ENSafrica](https://www.ensafrica.com/news/detail/12103/a-decade-in-the-making-constitutional-court-r)). If you torrent, you need a VPN with port forwarding. Mullvad dropped it in 2023 ([Mullvad](https://mullvad.net/en/blog/2023/5/29/removing-the-support-for-forwarded-ports)), while gluetun supports it natively for PIA, ProtonVPN, Perfect Privacy and PrivateVPN ([gluetun wiki](https://github.com/qdm12/gluetun-wiki/blob/main/setup/advanced/vpn-port-forwarding.md)). Usenet over SSL exposes your IP only to the provider. Most sources treat a VPN there as an optional extra layer ([TechRadar](https://www.techradar.com/features/how-to-stay-anonymous-on-usenet)). Debrid keeps your IP out of the swarm completely, but community reports say Real-Debrid bans accounts seen on two IPs at once ([Lemmy](https://lemmy.mariusdavid.fr/post/17317)), so adding a VPN can create a problem.

**Malware.** This is the decisive factor. Bitdefender documented fake unaired-episode torrents that hid a Lumma Stealer .scr inside a ZIPX padded to look like an 800 MB video. Lumma steals browser passwords, cookies, card data and crypto wallets on Windows 11 ([Bitdefender](https://bitdefender.com/en-us/blog/hotforsecurity/torrents-pirated-tv-shows-lumma-stealer)). Similar ".mkv.lnk" fakes relied on Windows hiding file extensions ([Bitdefender](https://www.bitdefender.com/en-au/blog/hotforsecurity/fake-mission-impossible-lumma-stealer-torrent)). In August 2026, fake copies of "The Odyssey" were named like "webrip-lama.exe" ([Euronews](https://www.euronews.com/next/2026/08/07/trojan-horse-alert-pirated-online-versions-of-the-odyssey-could-contain-hidden-viruses)). In October 2026, `South Park S29E03 1080p WEB H264-MeGusta.exe` reached **2,392 seeders** and was grabbed by Sonarr. It is a 118 KB stealer padded with an 886 MB overlay to defeat size-limited AV scanning, and it targets browser data, password managers, wallets, `.ssh`/`.aws` keys and VPN configs ([Thereallo](https://thereallo.dev/blog/someone-on-torrent-sites-kept-fucking-with-my-sonarr-setup)). These attacks work because anyone can upload to public indexers under a famous group's name. Usenet has the same kind of fakes, typically a "Codec/Setup.exe" or a passworded RAR, and SABnzbd's unwanted-extension and encrypted-RAR checks are built to catch them ([SABnzbd forum](https://forums.sabnzbd.org/viewtopic.php?p=93525)). Those reports date from 2014 to 2020, and I have no 2026 rate comparison. Debrid does not filter anything: a fake .exe torrent from a public indexer is cached and served like any other file. That is an inference, but it follows from how caching works.

## Debrid is cheapest, but one policy change emptied much of its cache

On paper, debrid looks ideal: AllDebrid costs **€2.99 per 30 days** ([AllDebrid](https://alldebrid.com/offer/)), TorBox roughly $3-10 a month ([LowEndTalk](https://lowendtalk.com/discussion/198214/celebrate-torboxs-birthday-with-30-off-giveaways/p1?new=1)), and cached files play instantly. Its weakness showed in 2026. From around 10 May 2026, Real-Debrid began rejecting cached torrents whose filenames match keywords such as WEB-DL and WEBRip, returning "File was removed from debrid service due to copyright infringement" ([ElfHosted](https://store.elfhosted.com/blog/2026/05/12/real-debrid-filtering-may-2026/)). Users anecdotally lost 50-70% of their cached content, and the filter is tied to French court action and EU DSA compliance ([corelab](https://corelab.tech/real-debrid-infringing-file-fix/)). WEB-DL is exactly the kind of release a standard Sonarr quality profile prefers, so the filter cuts straight into a default Arr setup. Many users moved to TorBox, which reportedly has no filename filter but expires items not accessed for 30 days ([ElfHosted](https://docs.elfhosted.com/guides/media/migrate-realdebrid-to-torbox/)). Note that most of the debrid commentary comes from ElfHosted, which sells hosted alternatives. On top of that, South African playback depends on international bandwidth to EU data centres. The crowd-sourced national median is about **24 Mbps with ~99 ms latency** ([speedof.me](https://speedof.me/internet-speed/south-africa)). That suggests on-demand 4K remux streaming from a mount will buffer on many lines. This is an inference.

Usenet has its own fragility. Dutch providers process notice-and-takedown requests largely automatically ([id.nl](https://id.nl/huis-en-entertainment/computer-en-gaming/netwerk/onvindbaar-op-usenet-echt-niet-61799)). The standard mitigation is to combine providers on different backbones. Prices are low on promotion. Black Friday 2025 offered Newshosting at $25.05 for 15 months, Eweka at €37.50 for 15 months, Frugal Usenet at $32/year, and NZBGeek at $9/year, with block accounts from about $5-15 ([Usenet Almanac](https://usenetalmanac.com/black-friday/)). Frugal lists an **Africa server location** ([Frugal Usenet](https://www.frugalusenet.com/)), but I found no measured performance figures for it. Speed depends on the route. An Australian user on 1 Gbps went from about 65 to 110 MB/s by switching to a provider with a closer server ([r/usenet mirror](https://reddit.sudovanilla.org/1iy5ybc)), which is a reasonable analogue for distant SA links. At those rates an episode finishes before you would have finished buffering a sequential torrent. I could not retrieve 2025-2026 Reddit consensus. Long-standing advice is "Usenet for popular content, private trackers for everything else" ([AnandTech forum](https://forums.anandtech.com/threads/who-still-uses-usenet.2269479/page-7)). Private trackers such as BroadcasTheNet are invite-only and require ratio upkeep ([Wikipedia](https://en.wikipedia.org/wiki/BroadcasTheNet)), so they are not a quick fix.

## Recommendation: clean up, then Usenet first, with torrents hardened as a fallback

**First, deal with the infection.** An infostealer exfiltrates cookies and saved passwords almost immediately (see Lumma's capabilities per [Bitdefender](https://bitdefender.com/en-us/blog/hotforsecurity/torrents-pirated-tv-shows-lumma-stealer) and the South Park sample's target list per [Thereallo](https://thereallo.dev/blog/someone-on-torrent-sites-kept-fucking-with-my-sonarr-setup)). Reinstalling Windows does not undo what has already been taken. From a clean device, rotate every password, revoke active sessions and API tokens, rotate any SSH or cloud keys, and treat any crypto wallet that was on the PC as compromised. Earlier 4.x Sonarr builds had an unauthenticated file-read flaw ([CVE-2026-30976](https://nvd.nist.gov/vuln/detail/CVE-2026-30976), fixed in 4.0.17.2952), but it affects only Sonarr running natively on Windows. This stack runs Sonarr in a Linux container, so it is not exposed; update when convenient rather than urgently.

**Second, make Usenet the primary source.** Add SABnzbd or NZBGet to the existing Docker Desktop stack, which works fine there, and add one or two indexers in Prowlarr. Buy a provider during Black Friday 2026, which usually starts about a week before 27 November ([nzbhydra](https://nzbhydra.com/blog/usenet-black-friday-2026/)). One provider plus a block account on a different backbone, and NZBGeek plus a second indexer, should cost roughly $60-100 for the first year. That figure is my estimate from the 2025 promo prices above. Turn on SABnzbd's unwanted-extension and encrypted-RAR abort options. Keep data on the WSL2 filesystem so hardlinks and file events work. You do not need a VPN for this path. Skip watch-while-downloading for now: with Usenet speeds the wait is a few minutes, and the tools that remove that wait (nzbdav, AltMount, Decypharr) are the ones Docker Desktop handles worst.

**Third, keep torrents only behind layered defences, and only once a VPN exists.** Route qBittorrent through gluetun with ProtonVPN or PIA port forwarding ([gluetun wiki](https://github.com/qdm12/gluetun-wiki/blob/main/setup/advanced/vpn-port-forwarding.md)). Until then, disable the public torrent indexers in Prowlarr. In qBittorrent, set Excluded file names to at least `*.exe *.scr *.lnk *.bat *.cmd` ([Thereallo](https://thereallo.dev/blog/someone-on-torrent-sites-kept-fucking-with-my-sonarr-setup)). In Sonarr v4, enable per-indexer "Fail Downloads" for Executables and Potentially Dangerous files. That check runs only at import, and an excluded file can leave the release stuck in the queue instead of failed, so community tools such as sonarr-extension-filter or cleanuperr close the gap ([Sonarr forum](https://forums.sonarr.tv/t/automatic-blacklist-malware/37822); [Sonarr forum](https://forums.sonarr.tv/t/i-created-an-app-to-block-and-remove-junk-rar-iso-scr-etc-downloads/39843)). In Windows, turn on file-extension display, because the .lnk tricks rely on extensions being hidden ([Bitdefender](https://www.bitdefender.com/en-au/blog/hotforsecurity/fake-mission-impossible-lumma-stealer-torrent)). Never open anything in a download folder outside Jellyfin. If you later want instant playback, TorBox through Decypharr is the better debrid choice, but plan on moving from Docker Desktop to Docker Engine inside a WSL2 distro first, and apply the same extension filters there.

## Conclusion

The question "how do I stream while downloading?" points at the wrong bottleneck. A user on slow, thin public swarms needs a sequential-download workaround. A user on a fast, curated source mostly does not. The same change that removes the wait also removes the swarm exposure and most of the fake-release risk, and both of those mattered more to this user than a few minutes of buffering. The malware wave also changed what "free" costs. Fakes padded to 887 MB with thousands of seeders show that public-tracker hygiene now requires constant filtering, and the price of a single missed filter is a stolen credential set. That makes a few dollars a month for Usenet look like insurance rather than a luxury.

Two uncertainties should shape what you do next. First, debrid's 2026 shows that any single-company cache can shrink overnight, so it belongs in the stack only as a replaceable layer. Second, the evidence for South Africa is thin: there is no current ISP notice-forwarding data, no measured Usenet speeds from SA, and no performance data for Frugal's Africa server. Measure your own throughput during a trial or a one-month plan before committing to a 15-month deal.
